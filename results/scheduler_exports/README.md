# Scheduler exports (synthesised deployable policies)

Storm `--exportscheduler` artefacts for the multi-objective queries,
generated by `../../scripts/scheduler_exports/run_sched_export_mo*.sh`
on **Storm 1.13.0** at the loam/Dry/x(0)=40 reference cell. These back
**Table `tab:moschedulers`** and the policy-slice figure
**`fig:policyheatmaps`**.

## Committed here (small text artefacts)
```
MO1/   sweep_mo1_loam_dry_x40.pareto.txt          weighted-sum sweep log (operating points)
       sweep_mo1_loam_dry_x40.pareto_summary.json per-weight induced-DTMC metrics
       sched_mo1_loam_dry_x40_safe095.{txt,props} named-policy synthesis result
MO2/   sweep_mo2_loam_dry_x40.pareto.{txt,_summary.json}
       sched_mo2_loam_dry_x40_Rv05.{txt,props}
G3_reference/  g3_loam_dry_x40_safe95.{summary.json,txt,result,props, mo.*}
               -> deployable sigma*_0.95 metadata (water=30.24 mm, P(unsafe)=0,
                  15,997,570 deterministic entries)
```
The per-operating-point numbers in `*.pareto.txt` /
`*.pareto_summary.json` (e.g. W_A:W_B = 2:1 -> water 18.13 mm,
unsafe 14.49, P[F !safe] 0.487) are the values tabulated in
`tab:moschedulers`. The rendered figure is at
`../../figures/policy_heatmaps.pdf`, produced by
`../../analysis/analysis_scripts/plot_policy_heatmaps.py`.

The `.scheduler`+`.states` pair is the deployable artefact described in
the paper ("the resulting lookup table constitutes the deployable
artefact of synthesis"). To obtain it, regenerate with the provided
driver:

```bash
bash ../../scripts/scheduler_exports/run_sched_export_mo1.sh --storm /path/to/storm
# (and mo2, mo3, mo4)  -- ~9 min build + sweep per cell on Storm 1.13.0
```
